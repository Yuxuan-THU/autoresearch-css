# 面向计算社会科学的 AutoResearch

> 给它一份数据集和一个模糊的研究方向，让它找出几个值得继续检查的问题。

这是一个面向计算社会科学的 AutoResearch 早期原型。

Karpathy 的 `autoresearch` 有价值的地方，不是“训练模型”这件事本身，而是它把研究循环压缩成一个清楚、可重复的过程：改一个东西，运行固定实验，保留或丢弃这次改动。计算社会科学不需要照搬训练循环，但可以借鉴这种纪律。

这里的循环是：

```text
研究方向
    → 候选问题
    → 数据审计
    → 廉价的经验检查
    → 排序后的 shortlist
    → 人类判断
```

理想的使用方式是让它夜间充当研究侦察员。第二天早上，它应该交付两三个值得继续调查的问题，而不是假装自己已经写完论文或发现了一个理论。

## 现在能做什么

当前 MVP 接收本地 CSV、JSON 或 JSONL 文件，并且：

- 检查列、样本量和缺失值；
- 区分数值变量和分类变量；
- 生成带有机制表述的候选研究问题；
- 做一次小规模的相关性可行性检查；
- 对候选问题排序；
- 输出包含数据集哈希和证据的 JSON 报告。

第一版故意保持简单。先让研究过程可以被检查，再增加自动化能力。

## 运行

```bash
python -m autoresearch_css.cli examples/demo.csv \
  --direction "国家信息能力与公众信任" \
  --count 10 \
  --out report.json
```

命令会打印排名靠前的三个候选问题，并将完整报告写入 `report.json`。

使用自己的数据：

```bash
python -m autoresearch_css.cli /path/to/data.csv \
  --direction "你的研究方向" \
  --count 20 \
  --out my_run.json
```

这个 MVP 不需要外部服务，也不依赖第三方 Python 包。

## 分数是什么意思

这里的分数只是用于分流，不是科学结论。它综合了：

- 所需变量是否存在；
- 初步经验信号的大小；
- 固定的理论价值先验；
- 暂定的新颖性先验；
- 小幅风险惩罚。

相关性检查只回答一个问题：**这个方向是否值得下一步看一眼？** 它不能回答关系是否具有因果性、是否可以推广，或是否适合发表。

新颖性字段也不代表“以前没人做过”。真正的判断需要文献检索、近距离阅读、引用追踪，以及研究者能够解释和捍卫差异。

## 重要限制

这个项目不是自动写论文的机器。

它不应该：

- 把相关性写成因果结论；
- 不查文献就宣布问题具有原创性；
- 没有来源、许可和访问规则就搜索开放网络；
- 跨数据集拼接个人记录；
- 看到结果后悄悄修改已经注册的分析；
- 没有人类审阅就发布结论。

一个有用的智能体可以失败，但不能隐藏自己为什么失败。

## 为什么不能直接复制 `autoresearch`

可以迁移的是实验循环：

- 明确智能体可以修改什么；
- 保持数据和评估协议稳定；
- 在边界内运行实验；
- 记录结果；
- 保留有用工作，丢弃较弱工作。

不能直接迁移的是单一、快速的指标。社会科学证据不是一个数字。严肃的研究还要记录理论、测量、识别、不确定性、稳健性、代表性、伦理和 provenance。这些检查更慢，而且可能互相冲突。这不是缺陷，而是研究对象本身的性质。

## 计划中的循环

下一版会逐步实现：

1. **Frame**：把研究方向转成研究对象、单位、机制、结果和约束。
2. **Diverge**：从理论、机制、群体、时间和方法等维度生成 20–50 个候选问题。
3. **Screen**：去重，并按照可行性、贡献、识别、成本和风险筛选。
4. **Lock**：由研究者选择问题，冻结 estimand、样本、主要结果和停止规则。
5. **Audit**：检查 schema、缺失、重复、覆盖、敏感字段和数据来源。
6. **Scout**：检索文献，生成带日期的“最近研究 / 差异 / 可能贡献”表。
7. **Run**：固定随机种子和输入，运行小规模可复现分析。
8. **Attack**：检查替代解释、安慰剂、敏感性以及明显的数据泄漏。
9. **Reproduce**：在干净环境中重新运行并比较产物。
10. **Report**：输出研究卡和决策日志。最终由人决定什么能够成为研究。

目前这里只实现了最前面的几步。

## 数据收集

MVP 只读取本地文件，这是有意的。

如果未来加入外部数据收集，应使用明确的数据连接器，而不是不受限制的浏览器代理。每个连接器都应该记录来源、条款、访问时间、版本、哈希、字段、速率限制、保留规则，以及是否经过人工批准。

默认应先做元数据和可行性检查。完整下载、敏感数据、身份关联和再分发，都应该需要明确的人工批准。

## 项目状态

这是一个研究原型，不是完成的框架。当前实现适合测试研究循环和报告格式，不适合确认性分析。

下一步最有用的功能不是更多“自动聪明”，而是：

- 回归和不确定性估计；
- 正式的 analysis manifest 和预注册锁；
- Parquet/DuckDB 支持；
- 带引用和时间戳的文献检索；
- 稳健性和安慰剂分析模板；
- 干净环境复现命令；
- append-only 实验日志；
- 数据访问与结果发布的人工审批闸门。

如果这些部分能够工作，智能体就可以运行一夜，而不会让第二天早上的研究者变成考古学家。
